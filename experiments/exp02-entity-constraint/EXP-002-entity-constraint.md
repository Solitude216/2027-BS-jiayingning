# Experiment ID
EXP-002

## Purpose
针对"黑塔/大黑塔""三月七/仙舟三月七""开拓者·存护/记忆/欢愉"等近名易混淆实体，验证实体约束检索（entity-constraint retrieval）能否真正提升易混淆题准确率，检验"实体消歧"在本系统中是否为有效手段；并汇总本轮 120 题冻结测试集上评测体系修复与 9 配置检索矩阵的主要结论。

## Compared with
EXP-001 中 `vector_field_k5`（向量·field·k5，不加实体约束）。

## Configuration
- 生成模型：DeepSeek `deepseek-flash`，temperature=0.2
- 嵌入模型：`bge-small-zh-v1.5`（512 维，本地离线）；BM25 用 jieba 分词；混合检索用 RRF（k=60）
- 知识组织：row / field / entity-grouped 三种切块；top-k=3/5/10
- 实体约束：问题抽取最长匹配角色名（`retriever.extract_entity`），检索后按 `doc.role == 抽取实体` 事后过滤；未抽到实体则回退未过滤结果
- 工程约束：索引只建一次，查询时仅切换 `retriever.entity_filter`，避免每题重建全语料索引
- 评测：hit/cite 按金标准三元组 `gold_source/gold_role/gold_field` 直接判定

## Dataset
冻结测试集 `data/samples/testset_2027-BS_v1.json`，共 120 题：可回答 45 / 不能回答 40 / 易混淆 35（v1.0，2026-10-05 冻结）。

## Random seed
不适用。检索与生成为确定性参数，结果可复现。

## Conclusion
1. **评测体系四项修复**：citation_accuracy（弱指标改名 source_role_match + 真引用指标解析"片段N"）、hit_knowledge（金标准三元组判定）、无 RAG 跳过检索均已解决；answer_correct 规则+同义词+多答案已实现，并经 25 题分层抽样人工双检（一致率 100%，见 `answer-correct-doublecheck.md`）。
2. **知识组织方式影响最大**：entity-grouped(0.958) ≫ field(0.850) ≫ row(0.575)；row 整行切块把多字段混在一段，可答/易混暴跌。
3. **混合 RRF 优于单路**：0.933 > 向量 0.850 > BM25 0.783；易混淆类 0.771→0.943，词法与语义互补。
4. **top-k 扫描**：总体 k3<k5<k10，但引用精度随 k 下降（0.917→0.833→0.783），k5 为平衡点。
5. **RAG 核心收益在防幻觉**：无 RAG 拒答率仅 0.05，RAG 达 0.925~1.000。
6. **实体消歧无效（诚实负面结论）**：加约束后易混淆类仍为 27/35=0.771，与不加约束完全相同；可回答类也完全一致（0.778）。问题文本已写出完整角色名、检索已命中正确角色，剩余 8 道错题（三月七、银狼、砂金·戏浪、开拓者·存护/欢愉、忘归人、玲可、佩拉）错在**字段级生成**（命途/属性答错），不在检索到错误实体。后续应转向生成端（字段化 prompt、结构化答案约束）。

## Problems
- answer_correct 规则匹配经 25 题分层抽样人工双检一致率 100%，评测口径可信（见 `answer-correct-doublecheck.md`）。
- 实体约束对"问题中已明确点名角色"的题天然无增量；本测试集易混题均直接写出完整角色名，约束退化为确认。
- 事后过滤存在误删风险：实体名写法不一致（如"开拓者·毁灭"点号全半角差异）会清空结果，是不能回答类略降的原因之一。
- 初版实体约束每抽到新实体即重建全语料索引（4723 篇重嵌），120 题跑数小时、日志截断进程被回收；已改为建一次索引+查询时切换 `entity_filter`，单配置降至约 15 分钟。
- entity-grouped 切块下片段 source 统一为 "ENTITY"，与金标准 CSV 名不可比，曾误判命中率为 0；已用 role-only 口径从明细重算修正。
