# Experiment ID
EXP-001

## Purpose
验证检索增强生成（RAG）中不同检索方法对游戏知识问答的影响，并与无检索的 LLM 直答基线对比，检验"检索增强"在答案正确性、拒答能力（防幻觉）与知识命中上的增益，以及向量检索与 BM25 关键词检索各自的优劣。

## Compared with
Baseline（无RAG直答：不检索知识库，直接调用 deepseek-flash 生成答案）

## Configuration
- 生成模型：DeepSeek `deepseek-flash`，temperature=0.2
- 嵌入模型：`bge-small-zh-v1.5`（512 维，本地离线）
- 切分：字段级（每个"角色+字段"一个独立短文档），并做文本去重
- 检索：top_k=5；向量法用余弦相似度，BM25 法用 jieba 分词
- 查询侧：向量法对问题加 BGE 指令前缀
- Prompt：RAG 与无RAG 使用分离的提示词模板（RAG 仅依据片段作答；无RAG 直答）
- 对比方案：无RAG基线 / RAG-BM25 / RAG-向量

## Dataset
冻结测试集 `data/samples/testset_2027-BS_v1.json`，共 120 题：
可回答 45 / 不能回答 40 / 易混淆 35。参考答案逐条对照知识库 CSV 核验，测试集已冻结（v1.0，2026-10-05）。

## Random seed
不适用。检索与生成均为确定性参数（jieba 分词、向量余弦、temperature=0.2），评测结果可复现。

## Command
```bash
python evaluation/run_eval.py --no-rag
python evaluation/run_eval.py --method bm25
python evaluation/run_eval.py --method vector
```

## Result

| 方案 | 可回答(45) | 拒答(40) | 易混淆(35) | 总体(120) | 命中率 |
|---|---|---|---|---|---|
| 无RAG基线 | 0.333 | 0.000 | 0.714 | 0.333 | — |
| RAG-BM25 | 0.733 | 0.925 | 0.571 | 0.750 | 0.822 |
| RAG-向量 | 0.711 | 0.950 | 0.771 | **0.808** | 0.800 |

明细文件：`results/tables/eval_norag_field_*.json`、`eval_bm25_field_*.json`、`eval_vector_field_*.json`

## Conclusion
1. **RAG 显著优于无RAG**：总体准确率从 0.333 提升到 0.75~0.81；尤其不能回答类——无RAG 从不拒答（0/40），RAG 拒答率达 92%~95%，有效防止幻觉，这是引入检索增强的核心收益。
2. **检索方法各有侧重**：BM25 在可回答类字面命中略优（0.733 对 0.711）；向量在易混淆类语义区分更强（0.771 对 0.571），两者知识命中率接近（0.822 对 0.800）。
3. **综合结论**：向量检索在总体与易混淆区分上更优，作为主实验的推荐检索方法；BM25 可作为字面精确检索的补充（混合检索待消融验证）。

## Problems
- 字段级切块下"属性类"问题系统性召回错位：查询含"属性"时，行迹表"属性加成"、晋阶表"1级属性"等噪声块压过"基础信息.属性"目标块，导致大量属性类问题检索未命中、被迫拒答。
- 多值/长文本字段（角色定位、配队推荐）被拆块后，模型只看到部分块，回答不完整或自相矛盾（如"白厄定位"同时出现"主C/辅助"）。
- 易混淆实体区分不足：BM25 对黑塔/大黑塔、三月七/仙舟三月七等近名实体易召回错误片段（0.571）。
- 评测口径局限：多答案/同义表达题目被字符串比对误判（如 Archer 遗器/光锥题），指标需放宽归一化口径。
